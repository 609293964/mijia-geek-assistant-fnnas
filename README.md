# Mijia Geek AI

> 米家自动化极客版 AI Agent - 用自然语言创建和管理复杂的米家极客版自动化规则

[![Next.js](https://img.shields.io/badge/Next.js-14-black)](https://nextjs.org/)
[![TypeScript](https://img.shields.io/badge/TypeScript-5-blue)](https://www.typescriptlang.org/)
[![Vercel AI SDK](https://img.shields.io/badge/Vercel%20AI%20SDK-3-purple)](https://sdk.vercel.ai/)

Mijia Geek AI 是一个 Web 界面的工具驱动 AI Agent，通过自然语言对话帮助你连接小米中枢网关、查看设备、创建和管理米家自动化极客版规则。用户输入米家中枢显示的 6 位动态码后，应用会建立长连接并保持网关会话。

---

## 核心特性

- **Web 交互** - 浏览器可视化查看设备、规则、变量和对话。
- **对话分支** - 编辑历史用户消息时创建独立分支，原对话和已执行操作保持不变。
- **Agent 循环** - 持续思考-行动，支持多方案建议和操作确认。
- **截图还原自动化** - 上传、粘贴或拖入自动化截图，由多模态模型识别后生成可确认的规则方案。
- **工具驱动** - 设备控制与规则管理均通过 Web Agent 工具调用实现，免 MCP。
- **设备能力预检** - 根据真实 MIOT Spec 校验设备属性、动作参数和规则引用。
- **设备引用扫描** - 查询某设备被哪些规则触发、读取或控制，排查残留引用；扫描不完整时明确提示未确认范围。
- **变量生命周期** - 支持创建、读取、赋值和安全删除全局变量及规则变量。
- **规则安全保护** - 创建和更新前执行结构、设备能力及变量引用校验。
- **长连接登录** - 输入 6 位米家动态码后由 NAS 服务端建立并保活网关长连接；关闭浏览器或刷新页面不会主动断开，网关短暂断线时服务端会在内存中尝试恢复。
- **fnOS Native 支持** - Next.js standalone 服务集成进 FPK 应用包布局。

## 在 fnOS 上安装和使用

1. **环境准备**：在 fnOS 应用中心安装 **Node.js v22**。准备 OpenAI 兼容的 LLM 接口及小米中枢网关的局域网 IP。
2. **安装应用**：安装 `fnnas.mijia-geek-ai.fpk`。配置 LLM 地址（如以 `/v1` 结尾）、API Key、模型名称、应用端口和网关 IP。
3. **连接网关**：打开应用 Web 页面，输入米家中枢显示的 6 位动态码并点击“连接网关”。验证码只提交给 NAS 服务端并只在进程内存中保留；应用会通过长连接完成认证并保持会话，关闭浏览器不需要重新输入。
4. **开始使用**：连接成功后，在聊天框中用自然语言查询设备和变量，或管理、创建极客版自动化规则。也可以点击图片按钮、粘贴或拖入自动化截图；图片识别需要配置支持视觉输入的模型。

若提示 `Node.js runtime not found`，请在应用中心重新安装 Node.js v22 并重启本应用。

> **连接保留边界**：该方案不需要抓包文件，也不会把验证码写入配置、Session 或日志。只要 fnOS 应用进程和网关 WebSocket 仍在，重新打开页面会读取服务端连接状态；如果 NAS 应用重启、网关主动使会话失效或网络中断后验证码已过期，协议本身没有可安全复用的离线恢复凭据，此时仍需从米家 App 获取新的 6 位验证码。

### 最近更新（0.0.15）

- **长连接登录**：使用米家中枢显示的 6 位动态码登录，不再需要上传 HAR；刷新页面后仍可读取服务端连接状态。
- **对话工作区**：支持搜索、重命名和导出历史对话；编辑历史消息会创建独立分支，不影响原对话和已执行操作。
- **自动化安全校验**：加强设备能力、变量引用、节点结构和写入后回读校验；设备引用扫描会明确标记未完成或未确认的范围。
- **稳定性和打包**：改进网关认证帧处理与短暂断线恢复，新增会话状态接口和 Windows FPK 自动递增打包脚本。

当前更新已完成本地测试和生产构建，尚未在真实 fnOS 或米家网关上安装验证。

## 开发与验证

### 聊天空回复排查

聊天会区分模型空正文（`EMPTY_RESPONSE`）、响应提前结束（`STREAM_INCOMPLETE`）、认证、接口/模型不存在、额度、上游服务和网络错误。错误保留在对话中，可使用消息复制按钮复制诊断编号；在服务标准输出中搜索 `[ChatDiagnostic]` 和相同编号，可查看请求阶段与耗时。诊断日志不包含消息正文、图片、密钥或接口地址。分类表示已观察到的错误，不能单凭空回复断定服务商故障；工具可能已经执行，重试前先核对结果。

模型接口的 HTTP 400/422、请求过大、上下文超限、工具调用格式和响应解析错误会显示相应的固定说明；未知错误会按输入、会话、模型或工具阶段给出排查方向，不回显服务商原始响应。若仍显示 `INTERNAL`，单凭分类无法断言根因，请保留诊断编号和当时是否使用工具或图片；涉及写入时先核对实际结果。

```bash
npm install
npm run test:unit
npm run build:fpk
```

Windows 用户也可以直接双击根目录的 `build-fpk.bat`：它会执行完整 FPK 打包流程，自动递增补丁版本，并把生成的 `fnnas.mijia-geek-ai_<版本>_x86.fpk` 复制到当前 Windows 用户的桌面。脚本优先使用 npm，其次使用 pnpm；如果两者都没有但 Node.js 可用，则直接执行各个 Node.js 打包阶段。脚本失败时不会复制旧的或不完整的安装包。

`build:fpk` 会先读取并校验 `package.json` 与 `package-lock.json` 的当前版本，自动递增一个补丁版本（例如 `0.0.10` → `0.0.11`），再完成 standalone 构建、整理 fnOS 应用目录并直接生成 `.fpk`。它不依赖额外安装 `fnpack`。Windows 下构建脚本会把 pnpm 符号链接安全地展开为普通文件，无需重复安装一套依赖。需要手动递增版本时，可执行 `npm run version:fpk`；`prepare:fpk` 和 `pack:fpk` 是不自动改版本的底层阶段。

## 项目结构

- `.agents/skills/` - 自动化规则、变量及模式知识库
- `fnnas.mijia-geek-ai/` - fnOS Native 应用包配置
- `scripts/` - FPK 构建准备脚本
- `src/app/` - Next.js App Router 与 Web API
- `src/components/` - Web 界面及网关登录交互
- `src/core/` - 网关客户端、设备、变量和规则核心工具
- `src/server/` - Web Agent、模型、会话和 Skill 加载逻辑
- `tests/` - 核心与 Web 端单元测试
- `docs/`、`ref/` - 项目文档、预览图和米家网关参考资料
